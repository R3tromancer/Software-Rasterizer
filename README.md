# Software Rasterizer

A from-scratch **CPU software rasterizer written in C++20**, built as an educational computer-graphics project. The goal is to understand the mathematics and implementation behind a rendering pipeline—not to delegate rasterization to a graphics API or rendering engine.

## Project goals

- Learn the mathematics and algorithms behind rasterization and the 3D rendering pipeline.
- Keep the code modular, readable, testable, and suitable for a computer-graphics portfolio.
- Implement core rendering algorithms on the CPU.
- Use external libraries only for supporting tasks such as window management and image/model loading.

## Current status

The project is under active development. The current implementation covers the early 2D rasterization stages:

- RGB color representation and a CPU framebuffer.
- Pixel access, framebuffer clearing, and PPM image output.
- Line rasterization using Bresenham's algorithm.
- Solid-color triangle rasterization using edge functions and incremental edge evaluation.
- SDL3 window/event handling and presentation of the framebuffer.

**In progress:** barycentric coordinates and interpolation of per-vertex colors. These features should be considered work in progress until the implementation has been built and visually verified in the project environment.

The longer-term goal is a 3D software rasterizer with custom vector and matrix math, transformations, camera and projection, depth testing, clipping, model loading, perspective-correct interpolation, texturing, lighting, and further optimization.

## Rendering approach

The core rendering path is implemented by this project:

```text
Geometry
   ↓
Our rasterization algorithms
   ↓
Our CPU framebuffer
   ↓
Display layer
   ↓
Window
```

The framebuffer stores the pixels generated by the software rasterizer. `Rasterizer` determines which pixels a line or triangle covers and writes them through the framebuffer API.

SDL3 is used for **window creation, event handling, and presentation**. It does not decide which pixels belong to our lines or triangles; those rasterization algorithms are implemented on the CPU in this project.

- **Window and presentation layer:** SDL3

## Project structure

The source tree is organized by responsibility. It will evolve as the renderer grows.

```text
src/
├── main.cpp             # Application entry point and render loop
├── Color.h              # RGB color type
├── Framebuffer.h        # Framebuffer interface
├── Framebuffer.cpp      # Pixel storage, access, clearing, PPM output
├── Rasterizer.h         # Public rasterization operations
├── Rasterizer.cpp       # Line and triangle rasterization algorithms
├── Display.h            # SDL-facing display interface
├── Display.cpp          # Window lifecycle, events, and framebuffer presentation
└── math/
    └── Vec2.h           # Initial 2D vector type; math module is in progress
```

Headers describe types and interfaces; `.cpp` files contain implementations where a separate implementation is useful. The rasterizer and framebuffer are kept independent of SDL so their core behavior can be tested or used without a window.

## Build and run

### Prerequisites

Install the following in the **MSYS2 UCRT64** environment:

- GCC / g++
- CMake
- Ninja
- SDL3

If SDL3 is not installed yet, run this in the MSYS2 UCRT64 terminal:

```bash
pacman -S mingw-w64-ucrt-x86_64-sdl3
```

### Build from the UCRT64 terminal

From the repository root, configure and build with Ninja:

```bash
cmake -S . -B build -G Ninja \
  -DCMAKE_C_COMPILER=/ucrt64/bin/gcc \
  -DCMAKE_CXX_COMPILER=/ucrt64/bin/g++ \
  -DCMAKE_BUILD_TYPE=Debug

cmake --build build
```

Run the resulting executable from the environment configured for SDL3. If the executable cannot find `SDL3.dll`, check that the DLL is available through the runtime `PATH` or is copied beside the executable by the CMake configuration.

### Build in VS Code

Open the repository folder in VS Code, select the configured MSYS2 UCRT64/Ninja CMake preset, configure it if needed, and use **CMake: Build**. The preset in this repository is intended to use the UCRT64 GCC toolchain.

## Learning roadmap

Planned stages include:

1. Framebuffer and pixel operations
2. 2D line rasterization
3. Filled triangle rasterization and edge functions
4. Barycentric coordinates and attribute interpolation
5. `Vec2`, `Vec3`, and `Vec4` mathematics
6. Matrix math and geometric transformations
7. Camera and perspective projection
8. 3D triangle rasterization and depth buffering
9. Back-face culling and clipping
10. OBJ model loading
11. Perspective-correct interpolation and texture mapping
12. Software shading and lighting
13. Normal mapping and shadow mapping
14. Profiling, optimization, and possible multithreaded/tiled rasterization
15. Documentation, tests, benchmarks, screenshots, and portfolio polish

The roadmap may change as the implementation develops and as one concept provides a better foundation for another.

## Engineering principles

- **Implement the important graphics algorithms ourselves.** No OpenGL, DirectX, Vulkan, or high-level engine is used to rasterize our geometry.
- **Keep modules focused.** The framebuffer owns pixel storage; the rasterizer owns coverage algorithms; the display layer handles presentation.
- **Prefer clear, testable steps.** New algorithms should be validated with small numerical examples and visual tests.
- **Optimize deliberately.** Correctness and understanding come first; performance work should be measured rather than assumed.
- **Document the reasoning.** The project aims to explain not only how an algorithm works, but why it works.

## Portfolio direction

The intended final repository will include explanations of the rendering pipeline, diagrams, screenshots, tests for mathematical components, and benchmarks for significant optimizations. Those materials will be added as the corresponding features are implemented and verified.
